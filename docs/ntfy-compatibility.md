# ntfy 功能补齐范围

基线：`2d3cd4b`，原版本 0.4.0。用户于 2026-10-29 要求补齐功能对比中的全部客户端功能，并由现有 Orca Worker `reviewer` 审查后处理意见。

## 验收范围

- 消息完整保存 `click`、`actions`（view/http/copy/broadcast）、`attachment`、`icon`、`tags`、`sequence_id`、控制事件。旧版配置、令牌、消息和删除标记迁移后保留。
- 系统通知和消息详情提供操作按钮；通知点击遵循 click，收件箱仍可查看详情。HTTP 默认 POST，支持 method/headers/body，明确反馈失败；仅成功后执行 clear，不自动重试有副作用的请求。仅用户点击执行操作。
- 附件展示文件名、类型、大小与有效期，支持受限大小的图片预览、下载、系统打开和分享；支持自定义图标、Emoji 标签。凭证不发送给无关资源地址，动作中的敏感数据本地加密。
- sequence_id 按服务器和主题隔离；支持更新、message_clear、message_delete；缓存重放、同秒事件和重启不让已清除/删除消息复活。打开的详情跟随更新和撤回。
- 多服务器可添加、选择、修改令牌、独立暂停与移除；后台同时接收所有启用服务器，游标、通知、主题与消息相互隔离。
- 应用内发送支持标题、正文、优先级、标签、Markdown 与 URL 附件；支持 Android 分享文本/文件至主题、文件上传。发送目标明确，点击发送才发布。
- 搜索标题、正文、标签；订阅可设置静音、最低提醒优先级、提醒标签和 Android 广播操作许可，系统渠道入口控制声音等。支持 ntfy:// 订阅链接，确认后才订阅。
- 保持简洁首页、浅深主题、320 dp 可用性和已有电源管理约束；不增加轮询、额外心跳或常驻 WakeLock。

## 验证与审查

JVM 测试覆盖协议、存储迁移、跨服务隔离、生命周期重放、操作请求和地址边界。按用户后续要求不做本地模拟器验证，也不操作手机或已有设备；本地编译/单元测试/静态检查后交 Reviewer 审查，由 GitHub Actions 运行发布检查与签名构建。所有命令完整输出进入 logs；审查意见与处理结果另行记录。

不在此次范围：服务端邮件/电话/定时投递、FCM/厂商推送、UnifiedPush 分发器、应用商店发布。
