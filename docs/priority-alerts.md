# 优先级振动与持续提醒（0.6.0）

入口：订阅 → 编辑主题 → 长振动提醒 / 最高优先级持续提醒。新订阅默认采用长短振动，持续提醒默认关闭。旧配置保持原渠道及原提醒行为，需要主动开启长振动；不会把原来被系统关闭的通知重新打开。

优先级 4 的振动节奏约 0.65 秒，优先级 5 约 3.5 秒。Android 8+ 渠道设置创建后主要由用户管理，应用不能覆盖用户在系统中关闭的声音、振动、渠道或勿扰限制。首次明确启用新版节奏时创建版本化渠道，并复制原渠道的声音、重要程度、分组、显示等设置；后续不反复重写。

持续提醒仅对用户明确开启的主题、符合筛选条件、接收连接建立之后的新优先级 5 消息生效。使用 Android 原生 `Notification.FLAG_INSISTENT`，由系统管理重复声音；不同 Android/厂商也可能重复振动。它不同于自建无限振动/音频循环：不新增计时器、MediaPlayer、WakeLock 或告警前台服务。系统通知栏展开、打开或清除通知可以停止；厂商行为须真机确认。

只对时间严格晚于流 `open` 事件的消息启用持续提醒；open 同一秒的消息保守地只提醒一次，没有有效 open 时间也只提醒一次。这样不依赖设备与服务端时钟一致，并避免重连后缓存消息持续响铃。普通补收提醒沿用原规则。

已读、全部已读、删除、控制事件、静音、筛选条件变化、移除订阅、停用/移除服务后，成功持久化的新快照会统一清理不再有效的通知。服务停止或进程重建时清理遗留持续提醒。普通取消和异步图标更新不重新启用持续提醒；已划掉的通知不会被图标请求重新创建。各服务按 server/topic/sequence 身份隔离。

持久化改用同步 commit 以确认写盘成功，再更新快照和清理通知；失败保留旧快照并显示错误。通知发送与清理共用 Store 锁，避免异步图标恢复已读/删除通知。

JVM 测试覆盖配置迁移、跨服务隔离、优先级、静音/已读/禁用条件、open 水位和有限振动模式。未运行模拟器或真机：需在 Android 通知权限允许、渠道允许声音/振动时，验证 priority=5 新消息、通知栏展开、划掉、打开、全部已读、暂停、重启、勿扰以及多条消息同时到达。不能把 JVM 通过等同于持续振动的真机效果。
