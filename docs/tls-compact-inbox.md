# TLS 后续排查与紧凑收件箱

本文记录 0.5.3。0.5.4 按用户后续要求取消全部已读悬浮按钮，入口收进右上角主题筛选菜单，无未读时禁用；网络与 TLS 逻辑沿用本文。

2026-10-30，基线 v0.5.2。用户反馈手机开启 Clash 后出现 TLS 提示，而手机浏览器可打开同一个自托管服务；收件箱主题切换与全部已读的独立操作行仍占空间，要求全部已读改成右下悬浮图标、主题切换紧凑美观。

## 证据与排查边界

- 开发机对用户提供的主机完成系统信任链与主机名校验，HTTPS 健康接口返回 HTTP 200。证书在有效期内。域名、证书详情与探测结果仅保存在本机忽略的 logs/ntfy-marlon-* 文件，不写入发布包。
- 开发机访问正常不能证明手机 Clash 路径收到相同证书链，也不能证明 Android 与浏览器使用相同信任库、DNS 或分流规则。
- 当前没有连接的 Android 设备，没有拿到手机具体 SSL 异常链。用户真机 TLS 故障尚未复现，不能宣称已证实根因或完全修复。
- 已复现的是诊断信息缺口：原 failureStatus 对所有 SSLException 使用同一条“检查证书与代理”的提示。两项分类回归在修改前失败，日志 logs/tls-classification-red.log；这不是手机故障的复现。

排查优先级为：新增显式网络绑定对 VPN 路径的影响、Android 与浏览器证书信任差异、Clash 按应用的分流或节点行为。需要手机上的具体错误或诊断码才能归因。

## 网络调整

- 撤回 0.5.2 新增的 Network.socketFactory / getAllByName 显式绑定，恢复 OkHttp 与 Android 默认的 DNS、socket 和代理路径。这是移除额外变量的兼容性回退，不是已证实根因的定向修复。
- 保留 DefaultNetworkState 的 LinkProperties 变化处理、配置就绪后连接、collectLatest 取消与游标补收、每会话独立池和 IO 清理。
- 保持默认 TrustManager、主机名校验与证书信任策略；不自动信任代理 CA，不使用 trust-all，不切换为 HTTP。
- 分别识别证书过期、尚未生效、证书链、对端身份、TLS 协议、TLS 握手与 TLS IO 错误；检查有界异常链和 CertPathValidatorException 的原因。提示只用固定文案和诊断码，不拼接异常消息、域名或令牌。
- 每个服务的最近失败摘要仅保留在内存中，重试进入“正在连接”时仍可在设置点击复制；标题明确是“最近连接错误”，不代表当前仍然失败。进程重启后清空。

## 收件箱布局

- 顶部只保留一行全部/未读筛选与右侧主题筛选图标。选中单一主题时图标有圆点；菜单勾选当前主题，读屏 stateDescription 包含当前主题名称。
- 全部已读使用右下角 12dp 小圆角悬浮按钮，双勾图标、无障碍名称和长按提示均为“全部标为已读”。有未读且未进入多选时显示；列表底部预留空间，不挡住最后一条消息。
- 执行范围仍为当前服务全部消息，不随主题、未读或搜索筛选缩小；沿用成功保存后清通知与演示模式逻辑。
- 原发送悬浮按钮移至菜单“发送消息”，保留发送入口，避免两个悬浮按钮堆叠。
- 主题失效时重置过滤条件，防止删除主题后列表持续空白。全部/未读各占可用宽度的一半，超长数字可省略。

## 验证

运行既有 JVM 测试、Debug 构建与 Release Lint。更新 settings_smoke.py 与 reading_smoke.py 对悬浮图标和主题筛选图标的断言；本轮不启动模拟器，不操作手机，不向主题发送消息。

后续设备验证：手机开启 Clash 后打开接收，若仍失败，到设置点击复制最近连接错误，保留诊断码供定位；复测当前服务全部已读、主题菜单选中态、无未读时悬浮按钮隐藏、多选时隐藏、发送菜单入口与 320dp 窄屏。
